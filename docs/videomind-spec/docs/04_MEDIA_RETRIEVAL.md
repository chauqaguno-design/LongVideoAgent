# 媒体处理、多模态记忆与证据检索设计

版本：1.0。状态：拟定规范，待实现与验收。适用里程碑：M2、M3，向 M4 的剪辑规划提供可追溯证据。本文的参数、质量阈值和容量均为首版提案，不代表现有 VideoMind 已具备或已经测得这些能力。

## 1. 设计目标与边界

目标是把长视频转换为可查询、可复核、可引用的媒体记忆，使“找出红衣人递出杯子的片段”和“这张截图来自哪里”能够返回原片区间，并支持继续回看片段确认动作和边界。最终回答必须区分观察到的事实、由证据推断的解释、仍未核查的区间。

通用推理与视觉理解统一使用 DeepSeek Flash。不同 Agent 可以共享同一 resolved model，采用不同上下文和工具权限；不依赖 Pro 或另一家通用模型兜底。文本 embedding 默认复用既有 BGE-M3；图像 embedding、可选片段 encoder、ASR、OCR、专用 reranker 和 FFmpeg 是独立能力。不能通过让 Flash 输出数字数组来实现 embedding，也不能把 OCR 文本的相似度命名为图像向量相似度。

优先复用现有 FastAPI/Python 分层、MySQL、MinIO、Redis、RabbitMQ/Celery、Qdrant 和前端。Codex 在 M0 对实际 checkout 做审计后，才能决定复用哪些类与接口；本文给出领域职责，不假定参考仓库路径就是用户仓库路径。

本子系统不负责生成最终剪辑时间线，不执行任意 shell，不以模型输出改变工作空间权限。检索结果可被编辑模块引用；只有已通过结构与证据检查的素材区间才能进入可执行剪辑计划。

## 2. 从原片到证据的处理链

| 阶段 | 输入 | 持久产物 | 何时可供下游使用 |
|---|---|---|---|
| 接收与校验 | 上传的原始 bytes、项目归属 | MediaAsset、不可变 MediaRevision、digest、对象存储引用 | bytes 完整、格式与可解码性通过检查 |
| 时间轴量测 | 原片与流元数据 | 流信息、真实 PTS 映射、镜头候选、音轨信息 | 原时间轴归一化规则确定 |
| 公平采样 | 时长、时间窗口、采样策略 | Segment、FrameArtifact、CoverageRecord | 实际帧成功解码，并记录实际 PTS |
| 多模态观察 | 帧、ROI、连续短片帧、音频块 | Observation、Evidence、带来源的字幕/文字/事件 | provider 返回并通过结构校验；失败单独记录 |
| 分层记忆 | 原子观察和区间关系 | 片段描述、事件候选、章节与素材摘要 | 子证据已固定，摘要可追溯至具体证据 |
| 索引构建 | 文本、图像、可选短片表示 | 版本化词法与向量记录、IndexGeneration | generation 在隔离空间完成校验 |
| 发布 | 完整性与质量清单 | 唯一 active generation 指针、outbox 事件 | 原子切换成功；旧 generation 仍供旧请求读取 |
| 查询与复看 | 用户意图、授权范围、当前 generation | 候选、融合排序、局部证据、查询覆盖账本 | 满足对应查询的证据与覆盖要求 |

这些阶段由持久作业驱动。API 提交后返回 ProcessingRun 或 WorkflowRun ID；不能让一个 HTTP 请求等待整条长视频处理完成。处理步骤的完成事件经 outbox 发出，重投递不得重复产生可见观察或重复发布索引。

## 3. 时间轴是所有模块的共同合同

### 3.1 规范时间

源区间统一为整数微秒的半开区间 `[start_us,end_us)`，绑定一个不可变 media_revision_id。0 表示该媒体版本选定的播放原点；不同流的原始 start_time 与偏移需保留。所有 JSON 数值不得超过安全整数上限。展示秒数与 `HH:MM:SS.mmm` 是派生显示值，不作为持久真值。

帧至少记录 media_revision_id、requested_us、actual_pts、time_base_num、time_base_den、归一化后的 actual_us、解码器版本和 artifact_id；source_frame_index 只有真正枚举得到时才填写，否则为空。禁止使用 `round(t * fps)` 伪造帧号。音频样本时间按其采样率与源偏移转换，不能假设音视频第一个样本同时出现。

换算规则在统一 schema 与实现中固定：先按流 time base 精确计算有理数时间，再减去记录的媒体原点，最终按约定的舍入方式转为整数微秒。必须保存换算参数，不仅保存浮点秒。负原始 PTS、B-frame 重排、VFR、长时间静止帧、非零 start_time 均在时间轴夹具中覆盖。

### 3.2 抽帧与代理视频

requested_us 表示请求位置，actual_us 表示实际命中帧位置；检索证据引用 actual_us。解码适配器必须固定“取请求位置处正在显示的帧”或“取不早于请求的第一帧”的策略，并用夹具验证，不允许不同命令隐式使用不同策略。两次请求命中同一实际帧时应复用产物，不计作两次独立视觉观测。

代理视频可为了播放器兼容而转成固定输出 profile，但原片、代理和导出时间轴是不同空间。代理必须携带到源媒体时间的映射或保持经过验证的时间一致性。检索命中先指向源时间，播放器再做映射；不能拿代理帧号回写原片。

媒体时长应表示最后一个可展示样本的结束时间，结合容器/流信息校验；不能直接把最后一帧 PTS 当作完整播放结束时间。损坏时间轴若不能可靠恢复，应标记 PARTIAL 或 FAILED，并阻止依赖精确边界的剪辑，而不是静默套用名义 fps。

## 4. 公平采样与覆盖账本

### 4.1 首版默认策略

默认将全片划为 60 秒窗口；末尾不足 60 秒仍形成独立窗口。每窗先安排至少 4 个均匀位置，再分配最多 4 个基于变化信号的额外候选。普通 60 秒窗口的基础位置可取 7.5、22.5、37.5、52.5 秒相对偏移；首尾的实际有效帧作为额外覆盖锚点去重记录。短片若实际帧数不足，应记录可用帧数，不制造重复帧来凑配额。

先为全片建立基础计划和预算，再执行任务；不能从第 0 窗口开始消耗一个全局 36 帧预算。事件候选来自镜头切点、像素变化、活动起止等信号，它们只决定“值得看哪里”，不代表业务动作已经发生。各窗独立获得最低份额；剩余预算按变化密度、查询需要和未覆盖程度分配，保留后段稀有事件被观察的机会。

默认片段索引为 10 秒窗口、2 秒重叠，即通常 8 秒 stride。镜头与语句边界可以调整片段边界，但必须保留重叠和完整范围映射；不能为了对齐一句话留下未分配区间。长事件通过多个 Segment 与同一事件候选关联，不要求塞入一个短片段。

片段索引与Flash观看计划是两个层次。10秒片段可能没有命中60秒概览中的任何一帧，此时视觉状态为UNOBSERVED，不能复制邻近描述或声称该片段已被模型观察。截图索引可在独立的图像embedding预算内，为每个片段补一个中心帧锚点并去重；这些帧仅记为DECODED及对应embedding能力，不自动升级为MODEL_OBSERVED。额外锚点消耗解码与encoder资源，不计作Flash已经看过；查询命中后仍需局部序列核查。

上述 4+4 仅是第一轮成本可控的观察起点。15 秒左右的基础间隔无法保证看见持续 0.5 秒的动作；动作、文本和用户指定细节都需要额外回看。若预算不足以完成全片基础计划，应降低明确的目标、保留全部未处理窗口并标记部分覆盖，不能把前半段成功伪装成全片完成。

### 4.2 CoverageRecord 记录什么

每条覆盖记录绑定 workspace/project/media_revision、ProcessingRun、采样策略版本、源区间与证据引用；查询复核另绑定规范化 query fingerprint、查询范围和验证协议版本。

| stage | 表示已完成的事实 | 不代表什么 |
|---|---|---|
| PLANNED | 已安排该区间的抽样/复查任务 | 已解码或已经看过 |
| DECODED | 实际帧/音频成功产出，有源时间记录 | 模型读取成功或语义已确认 |
| MODEL_OBSERVED | 指定模型完成该策略要求的输入处理，产出通过 schema 校验 | 区间内每个事件都已发现 |
| QUERY_VERIFIED | 对该查询，按指定协议完成局部或范围核查 | 对任意其他查询有效，或逻辑上绝无漏检 |
| FAILED | 该阶段失败，有原因、重试状态、缺失范围 | 可以把失败区间按无事件处理 |

stage 不应被当作单一全局“完成百分比”。视频可能视觉已观察但音轨失败，也可能普通概览完成但“全部挥手”查询尚未复核。覆盖记录应按 modality、采样/验证策略分开聚合；失败尝试保留，成功重试可使有效覆盖进度前进，但不抹掉审计记录。

至少提供：目标区间总长、计划/成功窗口数、不同实际帧数、最大相邻观测间隔、缺失区间、每路状态、预算停止原因、失败原因。所谓最大间隔只是时间采样统计，不能换算为“识别准确率”或“事件漏检概率”。

### 4.3 覆盖门槛与用户语言

普通“找几个相关片段”允许在已发布的部分索引上检索，结果必须显示覆盖状态。“第一个”“全部”“一共几次”必须进入查询级验证流程，具体规则见第 8 节。没有匹配与没有足够观测是两个不同结果，不能统一返回“没有发生”。

## 5. 多模态记忆：各类信号独立保留

| 表示 | 主要用途 | 来源与必备字段 | 明确限制 |
|---|---|---|---|
| ASR 文本 | 口述内容、关键词与语义检索 | 源音频区间、转写/对齐版本、语言、时间精度等级 | 非空文字不证明存在语音；整段转写不自动具有词级时间戳 |
| OCR / 视觉读字 | 字幕、幻灯片、界面文案检索 | 帧实际时间、原图 ROI、文字、识别来源、可读性 | 画面字幕可能是翻译/概括；不自动等于原声 |
| Caption / Observation | 场景、物体、可见关系与候选动作 | 帧/连续帧 IDs、Flash resolved model、prompt/schema 版本 | 单帧不能证明动作先后；描述未提到的细节可能仍存在 |
| 文本 embedding | 对 ASR/OCR/caption/摘要做语义召回 | 输入内容 hash、BGE-M3 版本、预处理与空间 ID | 向量相似是候选排序，不是事实判定 |
| 图像 embedding | 截图搜帧、可选文本搜画面 | 图像 artifact、encoder/checkpoint/预处理/维度/空间 ID | 图文跨模态查询必须由同一对齐空间支持；不表示时序 |
| 片段时序表示 | 动作型候选召回的可选升级 | 有序帧与时间、clip encoder 版本、片段范围 | 多帧池化不必然保留顺序；仍不直接给精确事件边界 |
| 层级摘要 | 全片导航、章节理解、上下文压缩 | 子证据 IDs、范围、生成版本、覆盖摘要 | 不是独立原始证据，不能据摘要补造细节 |

### 5.1 音频异常处理

VAD、响度、频谱或 no_speech 分数可用于标记静音、混音与转写风险，不作为永久跳过 ASR 的硬判据。背景音乐中可能有人声，低音量或单声道偏置可能使检测漏掉内容。保存音轨与声道信息；立体声一边有人声时，必须通过明确的下混或分声道策略验证，不能只默认读左声道。

连续重复文本可能来自 ASR 幻觉，也可能是副歌、口号或真实重复台词。去重应依据音频区间重叠、来源片段和人工/模型复核标记；不能仅因文字相同就删除。正常 VAD 与强制识别产生矛盾时记录冲突，结合音频回听或复转写处理，不把两种输出的一致/不一致直接包装成可靠概率。

若专用 ASR 只返回完整文本和总时长，则标记 segment 粒度，不得均分文字产生“精确词时间”。逐句剪辑必须增加可验证对齐过程，或明确降级到较宽片段。存在原有字幕时保留 OCR 与 ASR 两路；对于“屏幕写了什么”优先画面，对于“说了什么”核验音轨，冲突需可见。

### 5.2 观察、事件与摘要

Observation 保存一次处理的原始结构化结果；Evidence 将可引用主张绑定到它的媒体输入、源范围与 support 状态。support 只允许 SUPPORTED、CONFLICTING、UNCERTAIN、NOT_CHECKED。模型自报 confidence 若保存，应另标未校准，不能直接决定发布资格。

相邻重叠片段可能描述同一事件。事件归并综合时间重叠、参与对象、动作与源证据，保留“同一发生实例”的来源列表；文本相似而时间不相邻的动作不能自动归为一次。跨镜头同一人物默认未知；没有身份/追踪证据时不要凭衣服颜色给出全片确定身份。

章节与全片摘要引用子证据和未覆盖区间。重算某段会使依赖它的摘要失效；不要只更新向量而继续展示旧摘要。首版可以使用活动/镜头/语句划分加 Flash 归纳，不需要一开始就训练记忆模型或增加 ReID。

## 6. 索引布局、缓存与原子发布

### 6.1 逻辑分区

每种 embedding 空间分别建 collection 或等价隔离结构。维度、归一化方式、checkpoint、任务前缀、预处理或语言处理策略任一变化都形成新版本；不能混用旧向量。Qdrant payload 至少包含 workspace_id、project_id、media_revision_id、index_generation_id、segment/frame/evidence ID、时间范围和权限相关过滤字段。

词法索引、文本向量、图像向量和可选片段向量作为一个 generation 的组件清单。缺失组件必须在 capability manifest 中显式标注，查询路由据此降级；不能把“图像向量尚未部署”伪装成截图检索无结果。某路不支持中文文本查询时，应走已验证的中文路径或明确的查询翻译适配，不静默假设所有 encoder 都多语种。

### 6.2 Generation 生命周期

IndexGeneration 状态为 BUILDING → READY → ACTIVE → RETIRED；构建失败进入 FAILED。每个明确的 scope/collection 发布范围同时只有一个 active 指针。查询开始时固定一个 index_generation_id，按该 generation 的组件 manifest 读取对应 collection；不能在请求中途逐路重新读取“最新版本”。

构建步骤：建立隔离 generation → 生成并写入所有记录 → 读取回验数量/版本/范围/ACL payload → 校验覆盖与组件清单 → READY → 在 MySQL 事务中以 expected active generation 做 CAS 切换并写 outbox → 新查询见新版本。Qdrant 与 MySQL 不存在自动跨库事务，因此向量先完整写好，数据库指针最后切换；任何半成品都不得被普通查询读到。

查询必须显式按 generation 过滤，而不是只依赖一个可被提前切换的 Qdrant alias。旧 generation 在在途请求、可引用证据与回滚保留期结束前不回收。删除或权限撤销立即由数据库授权状态阻断访问，不能等旧 generation 清理完成才生效。

### 6.3 缓存键与失效传播

帧缓存键包含媒体 bytes digest、解码器/转换版本、实际 PTS、ROI 与缩放参数；ASR 包含音轨内容 hash、切块/VAD/转写/对齐版本；视觉观察包含输入 artifact hashes、帧顺序与时间、模型 resolved ID、prompt/schema 版本；向量包含输入 hash、embedding 空间与预处理版本。

缓存命中只能复用相同语义输入。改变采样计划不必重新解码已有相同 PTS，但新增帧会触发新的观察与依赖摘要。改变 caption prompt 不需要重跑 ASR；改变 media revision 必须阻断所有旧来源被当作新片证据。失效传播按产物依赖图进行，新的结果进入新 generation；不原地覆盖 ACTIVE 中的向量。

## 7. 检索、截图搜索与复看

### 7.1 授权范围先于召回

服务端从登录主体解析 workspace/project/media 权限，再规范化用户过滤条件。模型只能提出已授权范围内的内容条件，不能提供或覆盖鉴权身份。每路 topK 前都带 workspace、project、media revision 和 generation 过滤；禁止全局取 topK 后再剔除其他租户命中。返回前再次校验权限，处理撤销与删除竞态。

### 7.2 多路召回与融合

文字查询可并行访问 ASR/OCR/caption 的词法与文本向量，支持图文对齐的 encoder 可增加画面召回。截图查询先校验格式与像素预算，保留原图及可选 ROI，生成与帧索引同空间的图像向量；OCR 提取的文字只能作为辅助路，不能替代真正的图像路径。

首版候选数可每路取 50，作为可调参数记录在 query trace 中。使用 RRF 融合不同分数尺度，初值 k=60；同一 source evidence 被多个 chunk/索引重复命中时先保留来源、再去重，不能让它因复制次数多而获得无限加权。融合后按媒体、重叠区间和事件候选聚合，同时保留相邻上下文。

专用 reranker 可做候选相关性排序；Flash 对少量最高候选读取实际帧与相关转写作语义复核。排序分数不作为事实概率展示。单张截图可能在片头片尾重复、出现于回放或静态画面中，应返回多个匹配区间与“不唯一”的状态，不强制只给一个时间点。

### 7.3 局部回看

对动作查询，围绕候选扩展前后上下文，读取有序帧并附实际时间；对文字查询，裁原分辨率 ROI；对台词查询，读取音轨对应片段和已对齐文字。根据当前不确定性增加采样密度，有最大轮数、总帧数和 token 预算，超限返回未解决状态。

边界细化采用“粗候选 → 局部较密采样 → 主张是否成立 → 边界附近再取样”的有界过程。模型只提出区间候选，服务端校验源范围、顺序、证据所属媒体和实际观察帧。返回边界误差/分辨率等级；无法区分的前后界给出包络区间，不制造帧级精度。

## 8. 首个、全部与计数

/search 始终同步返回候选；FIRST/ALL/COUNT 的 verification_required=true，核查由持久 WorkflowRun 执行。SearchResult 使用 coverage_summary、truncated、candidate_count 和可空的 workflow/result artifact 引用，candidate_count 不是事件总数。coverage_summary 分别列 requested_ranges、verified_ranges、unverified_ranges，semantic_exhaustiveness_guaranteed 固定为 false；query_id 是检索 ID，query_run_id 是验证 WorkflowRun ID。

最终 AnswerResult 用 found_event_count、count_qualifier（OBSERVED_ONLY/WITHIN_PROTOCOL）与 complete_event_list_artifact_id 表达数量和完整清单。结果展示是否截断与扫描是否按协议完成是两件事，不能用 topK 命中页代替完整实例清单。

| 查询 | 必须检查的范围 | 可以下结论的条件 | 未满足时的表达 |
|---|---|---|---|
| 找一个/几个 | 已授权的搜索范围 | 命中自身有支持证据 | “目前发现这些片段”，列覆盖限制 |
| 第一个/最后一个 | 候选之前/之后的完整目标范围 | 对该查询按验证协议完成前缀/后缀核查，并明确协议能力 | “目前发现最早的一次”；未核查区间不能省略 |
| 全部 | 用户定义的全部素材/区间 | QUERY_VERIFIED 覆盖所要求范围、失败区间为空、实例归并完成 | 列已发现实例与尚未核查区间，不称已列全 |
| 一共几次 | 全部目标范围与实例定义 | 满足全部的门槛，并完成跨块重复实例归并 | “已确认至少 N 次”；不输出看似精确的总数 |
| 从未发生/没有 | 全部目标范围 | 明确按何种采样与验证协议未发现；不能推广为绝对不存在 | “在已核查范围内未发现” |

查询指纹必须包括目标动作/对象条件、语义约束、目标范围、协议版本与模型/采样版本。验证“红衣人出现”的覆盖不能复用于“红衣人先拿杯子再转身”。对于持续时间短于当前采样可观察粒度的事件，应提升观测密度或明确无法满足该查询的完整扫描要求。

计数单位须固定为发生实例，例如“进入画面一次”与“连续停留的每个片段”不同。默认不清楚时先返回解释并向用户澄清，或采用可见且可修改的定义。连续实例跨重叠块只计一次，间隔后的真正重复应保留多次。所有“完整”状态描述的是执行了特定协议，不是数学证明语义无漏。

## 9. 错误、恢复与资源限制

ProcessingRun 使用 QUEUED/RUNNING/PARTIAL/SUCCEEDED/FAILED/CANCELLED。某些非关键模态失败但基础媒体可用时允许 PARTIAL；这是本次运行终态，补处理须新建关联运行并复用有效缓存，不能把旧失败历史改成成功。必须展示哪些能力不可用，并阻止依赖缺失证据的后续动作。文件损坏、时间轴不可恢复、越权等不应被模型重试掩盖。

每阶段以输入版本+步骤版本+参数 hash 建幂等键，使用持久 lease 和完成记录；worker crash 后先检查已经提交的产物再重算。取消需传播到正在运行的 FFmpeg、ASR 和模型请求；不支持远端真正终止时应停止接收其结果用于发布，并准确记录仍可能产生的费用。

限制媒体时长/大小、解码像素、模型输入图数、并发窗口、临时磁盘和任务总预算。所有外部进程使用受控 argv 与 artifact resolver；上传文件名、字幕和模型文本不得进入 shell。日志记录 artifact ID 与摘要，避免把私有视频帧/base64 或原始敏感转写直接写入通用日志。

## 10. 质量评测与发布门槛

建立版本化 evaluation manifest，记录素材许可、bytes digest、标注者、划分、查询、真值区间、困难类型、模型与索引版本。固定盲测集为 24 条素材、总长至少 12 小时，其中至少 6 条时长≥1小时、其中2条≥2小时；共320条查询：200条文字、60条截图、60条首个/全部/计数查询。开发调参使用另外的独立小集，不反复用盲测集调整阈值。截图包含裁切、缩放、压缩、近重复、不同来源相似画面与无匹配样本。不得用同一次模型输出自标真值并自评。

还需确定性夹具：CFR/VFR/非零起始 PTS、无音轨、单声道人声、混音、合法重复台词、纯 BGM、字幕与口述冲突、低运动短事件、末尾稀有事件、损坏输入、跨块同一动作、跨租户相似画面。长视频事件均匀分布与末段稀有事件必须单列，不能只看全体平均。

以下均为拟定发布目标，失败时修实现或走明确的 spec 变更流程，不允许悄悄下调：

| 指标 | 首版目标 | 测量口径 |
|---|---|---|
| 文本候选 Recall@20 | ≥0.90 | 普通局部查询：去重后的GT相关事件中，被前20候选命中的比例，再按查询取宏平均；全局穷尽查询另评 |
| 截图候选 Recall@20 | ≥0.85 | 去重后GT来源出现实例的覆盖比例；同media revision内命中GT区间，孤立真值帧允许±2秒；不同来源的相似画面不算命中 |
| Grounding R@5，tIoU≥0.5 | ≥0.80 | 最终前 5 区间与真值的时间交并比 |
| 支持证据的主张 precision | ≥0.95 | 人工审查最终输出主张及直接证据 |
| 边界绝对误差 P95 | ≤3 秒 | 仅持续≥2秒且边界可清晰标注的事件；短事件另报 |
| 覆盖不足却声称首个/全部/精确总数 | 0 次 | 故障注入与全局查询集合 |
| 跨租户可见证据/向量/产物泄漏 | 0 次 | 所有检索路、回看、缓存、删除与权限撤销测试 |
| generation 混读、半成品可见 | 0 次 | 构建中断、并发发布、切换时查询、回滚 |
| 时间换算一致性 | 符合统一时间合同 | 对已知 PTS 夹具逐项核验，舍入误差至多 1 微秒 |

Latency、每小时视频处理成本、每次查询 tokens、回看轮数、索引体积和缓存命中率必须真实记录。硬件与 provider 并发未确定前不承诺固定秒数；M0/M6 在明确的参考环境冻结 SLO，并分别报告冷启动、已索引普通查询和全局扫描。mock 可验证流程，不能代替模型、ASR、embedding 和真实 FFmpeg 的验收。

## 11. 与既有 Watch 项目的关系

可借鉴 video-watch-plus 的量测、概览拼图、连续序列复看、原图 ROI 读字、manifest 溯源；不能直接照搬全片固定 16 骨架/36 帧、事件先占前段预算、固定每图 346 token 或依赖名义 fps 的帧号。其音频判据应视为异常信号，不作为语音存在与否的硬裁决。若移植实际代码，保留上游许可与修改记录。

watch-skill 的 caption/转写检索可作为一个文本证据源；视觉事件检索仍需要真实图像/片段表示与回看。两者不再各自启动一个主 Agent；统一由 VideoMind 的工具与工作流调用。

参考源码与一手资料：

- [video-watch-plus 的 vw.py](https://github.com/xinhailaopo/video-watch-plus/blob/main/vendor/vw.py)：本包此前静态核查的 probe/plan/sheet/seq/read 实现，后续实施必须重新固定 commit。

- [DeepSeek ASR](https://api-docs.deepseek.com/api/asr/)：独立语音接口，不能当作 Flash 原生视频/音频能力；时间戳精度按实际响应合同检查。
