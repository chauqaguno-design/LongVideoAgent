# VideoMind 用户流程与界面状态规范

版本：1.0　日期：2026-11-23　状态：待实施、待验收

本文落实 [01_PRD.md](01_PRD.md) 的交互与异常行为。页面名称描述产品职责，实际实现优先复用既有前端。所有能力状态来自后端，不能由前端对话文本猜测；本文示例文案是设计要求，不代表已有界面或结果。

## 1. 信息架构

| 页面/区域 | 用户可见内容 | 主要动作 |
|---|---|---|
| 项目列表 | 项目名称、素材数量、最近操作、进行中任务 | 新建、进入、重命名、删除 |
| 项目素材库 | 素材时长、版本、可播放/可检索模态、处理缺口 | 上传、播放、查看处理、重试、加入编辑 |
| 检索与问答 | 当前范围、文字/截图输入、回答、候选和证据 | 搜索、跳转、局部复看、选片段 |
| 编辑工作台 | 需求摘要、源播放器、片段清单、输出预览、版本 | 修改、保存、回退、预览、导出 |
| 任务中心 | 用户任务、子步骤、进度、消耗、失败原因 | 详情、取消、恢复、调整预算 |

项目范围始终可见；跨项目检索需明确选范围。内部模型名、队列名和数据库字段不塞进常规操作步骤；来源类型、覆盖、费用和版本会影响判断，必须在相应位置可见。关联 REQ-PRJ-001、REQ-UX-001、REQ-OPS-001。

## 2. 流程 A：上传后异步处理

1. 用户进入项目，选择文件；界面显示部署支持的格式、大小与时长限制。上传进度与后续处理进度分开。
2. 上传中可取消；断线后按既有上传协议续传或恢复，重复提交通过服务端幂等/去重处理。校验失败显示“文件无法解码/上传不完整”等实际原因。
3. 媒体校验可用后，卡片出现播放和显式区间剪辑入口；无需等待 ASR、视觉索引全完成。
4. 后台建立分阶段作业。卡片显示“处理中：文字转写可用，视觉观察尚未完成”等能力信息，可进入任务详情查看时间覆盖。
5. 页面离开或关闭不等于取消作业。再次进入项目按 run/job ID 拉取状态，恢复进度；不得重新提交一份处理任务。

| 状态 | 主文案示例 | 可执行动作 |
|---|---|---|
| QUEUED | 已上传，等待处理 | 播放已校验素材、查看队列、取消 |
| RUNNING | 正在处理；已完成的模态见下方 | 查看覆盖、使用已可用能力、取消 |
| PARTIAL | 部分区间处理失败；已有结果可使用 | 查看失败区间、重试失败步骤、缩小查询范围 |
| SUCCEEDED | 本次处理完成；采样范围与密度可查看 | 检索、编辑、查看覆盖 |
| FAILED | 本次处理失败：具体原因 | 查看日志摘要、修正输入后重试 |
| CANCELLED | 已取消；已保留的结果见下方 | 查看已有结果、按需重新处理 |

“完成”只针对本次处理计划。覆盖详情按时间轴显示计划、解码、模型观察、针对问题验证和失败区间，不把视觉采样进度标为“理解进度”。重建索引时显示“使用上一版本索引，新版本构建中”；失败时继续保留原 active 索引。关联 REQ-ING-001 至 REQ-ING-005、REQ-UX-002。

## 3. 流程 B：文字或截图找片段

### 3.1 输入与范围

搜索框上方显示当前项目和已选素材；文字检索与截图检索是两个清晰入口。用户提交截图后看见缩略预览和可移除按钮，明确截图用于当前查询；图像索引不可用时给出原因，不暗中改成纯 OCR 后仍称图像检索。

查询“第一次/全部/共几次”时，将范围解释显示在问题下方，例如“范围：本项目已选两条视频，完整时长”。无范围的歧义优先使用当前明确范围；可能显著改变答案时才提出一个聚焦问题，不能随意扩大到其他项目。

### 3.2 候选卡片

每条至少显示素材名、源起止时间、缩略图、匹配摘要、匹配来源与证据状态。来源可为转写、OCR、视觉观察、图像相似或局部序列复核；只有数字相似度时不显示百分比“确定发生”。

用户点击卡片在源播放器跳转，当前片段高亮；“查看依据”展开具体文本、帧/序列及对应时间。“进一步核查”触发局部复看，展示作业状态和新增证据。不能用稀疏最近邻帧冒充指定时刻的实际画面。

### 3.3 空结果、部分覆盖与冲突

| 情况 | 应展示 | 不应展示 |
|---|---|---|
| 尚未建立相应索引 | 此模态尚不可检索；可启动或查看处理 | 视频没有相关内容 |
| 已检索范围内无候选 | 当前检索未发现匹配，可调整范围或复看 | 事件从未发生 |
| 全部/计数尚未穷尽 | 当前发现数量、已核查范围、未核查区间 | 将 topK 条数标为总次数 |
| 转写与字幕不一致 | 两份原始证据、各自来源与时间 | 无条件自动覆盖其中一份 |
| 动作仅有静态相似 | 候选画面相似，动作过程尚未确认 | 已确认动作先后 |

结果可多选加入编辑草稿；未验证候选加入时保留状态，后续需要按 EditBrief 复核。关联 REQ-RET-001 至 REQ-RET-006、REQ-MEM-002、REQ-MEM-005。

## 4. 流程 C：带证据问答

回答区域先给可支持的结论，再给可点击时间引用。点击引用打开对应源版本的片段与证据侧栏，不跳到输出预览时间。事实、口述信息和推断以自然文字区分；不要求用户阅读原始 JSON。

证据状态使用“有支持证据”“证据存在冲突”“尚不确定”“尚未核查”。“有支持证据”表示当前检查支持该主张，不能写成绝对正确。回答缺少证据时说明具体缺口，例如“这段没有可读字幕，现有帧不足以确认设置值”，并提供原图裁切或局部复看入口。

追问继承当前项目、素材范围和明确所指的对象；指代不清且会改变选片时提出澄清。索引更新后继续追问，界面说明来源版本变化，并重新校验证据；旧回答引用仍指向原始版本。素材被删除后显示“原始来源已不可用”，不自动替换为相似素材。关联 REQ-RET-006、REQ-AGT-003、REQ-AGT-006、REQ-UX-003。

## 5. 流程 D：M1 显式区间剪辑

1. 用户从素材播放器或编辑工作台添加源区间，填写起止并选择顺序。显示源区间时长和当前成片总时长。
2. 保存前即时提示空区间、越界和无效输入；最终以服务端校验为准。不同源帧率可接受，但输出采用统一 profile。
3. 保存成功显示版本号；时间线是已保存版本的视图。用户点击“生成预览”，后端返回 RenderJob，按钮变为查看任务，不重复提交。
4. 渲染经过 QUEUED、RUNNING、VALIDATING。只有 SUCCEEDED 才出现可播放预览与导出入口；校验失败展示具体失败项。
5. 修改、回退和再次渲染都明确绑定版本。导出文件展示版本、输出规格、实际时长和下载入口。

源播放器与成片预览须有明确标题。片段列表同时支持查看“源 00:30–00:40”与“成片 00:08–00:18”。无音轨素材采用统一静音/无音频策略并在计划摘要说明。字幕策略为不额外生成、保留源画面、烧入已对齐字幕；“不额外生成”不可写成“去掉原字幕”。关联 REQ-EDT-001、REQ-EDT-003 至 REQ-EDT-007。

## 6. 流程 E：M4 自然语言按需剪辑与修改

用户提出“把这段访谈里介绍产品的部分剪成 60 秒，保留原声”。系统形成可见的需求摘要：素材范围、主题、目标时长、允许偏差、原声和字幕策略。已有明确约束直接执行；必须决定的歧义才进入 AWAITING_INPUT。

随后依次检索、核查、选段、计算总时长、建立时间线并生成可审阅预览。用户在同一工作台看见阶段进度和候选来源。若找不到足够素材、目标时长与“保持句子完整”冲突，系统说明冲突，给出扩大来源、放宽时长或减少内容等具体选项，保留已完成工作。

修改例：“删掉第二段，开头多留两秒。”操作基于界面当前版本。服务端返回新 revision；若此时已有另一修改，409 后显示“时间线已更新，请基于最新版本重新应用”，保留用户输入并展示差异，不静默覆盖。相同请求重试复用相同结果。

预览上方固定显示“当前时间线 v3／正在播放 v2”，允许查看旧预览，但不能让用户误以为新修改已渲染。旧任务晚完成只更新其自身记录。回退到历史内容也产生新版本；取消渲染不删除编辑决定。关联 REQ-EDT-002、REQ-EDT-003、REQ-EDT-006、REQ-UX-003。

## 7. 任务中心、预算与 Agent Team

任务详情按用户目的组织，如“生成产品介绍剪辑”，下层才是检索、复看、渲染和验证。WAITING_JOB 显示正在等待哪项结果；AWAITING_INPUT 显示需要用户决定什么；FAILED 显示错误与可恢复步骤；SUPERSEDED 显示已被哪个新版本任务替代。

预算区域展示上限、已记录消耗、仍在运行的请求和估算依据；没有可靠价格数据时显示原始 usage 与“金额暂不可估算”。预算到限不继续启动调用，保留当前状态；用户可缩小范围或调整上限。取消后显示“正在停止”直至后台确认，已产生费用不清零。

M5 可展示“正在并行核查 3 个候选片段”这类有意义的进度，不要求用户管理邮箱或 lease。所有角色仍用 Flash，共享总预算；只有主提交路径更新时间线。单个队友失败时显示受影响子任务，已有独立结果保留；重试不能把过期结果写入新版本。单 Agent 模式始终可以完成基本流程。关联 REQ-AGT-003 至 REQ-AGT-005、REQ-TEAM-001 至 REQ-TEAM-003。

## 8. 错误、恢复与删除

| 异常 | 用户恢复路径 |
|---|---|
| Flash 图片或工具调用合同失败 | 显示受影响能力不可用与部署检查原因；允许继续使用不依赖该能力的显式剪辑路径 |
| 某个时间块失败 | 定位该区间并重试，已有块与当前 active 索引继续可用 |
| 浏览器/SSE 断开 | 重连后按最后事件位置与作业快照恢复，不重发变更操作 |
| worker 崩溃 | 后端恢复/对账；界面展示重试状态和原 job ID，成功产物不重复出现 |
| 下载链接过期 | 校验当前权限后刷新链接；来源已删除则明确不可下载 |
| 素材删除影响剪辑 | 列出受影响项目和引用，再执行删除；相关编辑显示缺失来源，不自动替换 |
| 越权或不存在的资源 | 返回受控错误，不透露另一租户资源内容或是否存在 |

删除属于明确影响已有内容的动作，须展示影响范围；正常检索、已授权预览和可逆编辑不逐步增加确认。错误文案提供原因、影响和下一步，详细技术日志通过任务详情展开，避免把堆栈直接当产品提示。关联 REQ-OPS-001、REQ-OPS-003、REQ-OPS-006。

## 9. 界面验收清单

- [ ] 四个主要工作区可完成上传、查询、编辑、导出，并始终显示当前项目。
- [ ] 局部处理失败、能力阻塞、空结果、无答案、预算耗尽都有独立可操作状态。
- [ ] 采样覆盖、查询验证覆盖与语义置信不混用；“第一次/全部/计数”结果展示范围和缺口。
- [ ] 每个证据跳转指向正确媒体版本与源时间，每个预览/导出显示其 timeline revision。
- [ ] 双击、重复请求、断线重连、旧任务晚到不会重复编辑或覆盖当前预览。
- [ ] 键盘可操作表单与主要按钮，错误关联到输入项，状态不只依赖颜色表达。
- [ ] 所有示例验收使用真实媒体与实际文件；mock 页面不计业务链路通过。
