# 验收评测与发布手册

本章中的数值是拟定发布门槛，不是当前系统实测结果。首轮实施应冻结硬件、数据、模型与配置后执行，报告实际结果。无法达到时如实标记FAILED或BLOCKED，并分析瓶颈；不得通过删除反例或放宽门槛把失败改成通过。

## 1 验收分层

规范静态校验检查REQ、task、AT、Schema和引用。领域测试检查时间区间、CAS、幂等、状态和覆盖逻辑。集成测试使用实际数据库、队列和对象存储。媒体测试生成真实文件并解码。provider live测试调用实际Flash和专用模型。端到端测试从界面上传到证据或导出。基准评测检查检索、定位、回答与成本。发布演练检查迁移、恢复与隔离。

mock只用于可控故障、协议边界和快速单元测试。它不能替代真实视频渲染、真实向量检索或真实模型能力验收。

## 2 测试素材

合成真值素材至少覆盖固定/可变帧率，24/25/30/30000比1001帧率，视频起始PTS非零，旋转元数据，横竖屏混合，静音，无音轨，人声混背景音乐，重复口令，近似截图，短暂事件，尾部事件，字幕偏移，损坏媒体和超出范围的裁图。合成素材的每段ID、时间码和颜色标记可机器核对。

真实盲测集初值为24条视频、合计至少12小时；至少6条超过或等于1小时，其中至少2条超过或等于2小时。320条查询由200条普通文字查询、60条截图查询、60条全局查询组成。视频内容涵盖讲解/会议、电影或故事类、运动或动作、录屏/教程；有合法使用权限。调参使用独立开发集，不使用盲测结果反复调阈值。

每条ground truth保存媒体版本、查询、相关事件区间、允许替代答案、是否穷尽、事件定义、边界模糊性和标注者。全部/计数必须给定事件去重和排除规则，例如回放是否算同一进球；歧义先解决或列为允许的多种解释。

## 3 质量门槛

| 项目 | 拟定门槛 | 统计口径 |
|---|---|---|
| 文字候选召回 | Recall@20至少0.90 | 普通局部查询的去重GT事件集合，逐查询召回后宏平均 |
| 截图候选召回 | Recall@20至少0.85 | GT区间命中；孤立帧使用预先冻结的正负2秒容差，错视频不算命中 |
| 最终时间定位 | R@5且tIoU不低于0.5至少0.80 | 有正GT的局部查询中，前5区间任一个与任一GT在同源上达标即查询成功；分母为查询数 |
| 回答证据支持 | claim precision至少0.95 | 将回答拆成可验证主张，独立审查其引用是否支持；不能只检ID存在 |
| 全局结论误报 | 0例 | 覆盖不足却无条件声称全部、首次或精确总数的案例数 |
| 跨租户访问 | 0例 | API、检索、artifact、缓存、worker和删除测试均不得越权 |
| 清晰事件边界 | P95绝对误差不超过3秒 | 持续至少2秒且真值清晰的事件；起止分别统计，短事件单列 |
| 编辑结构完整性 | 必须全通过 | 源区间合法、版本一致、约束校验、可解码、音视频/字幕映射 |
| 重复执行副作用 | 0个重复可见结果 | 同幂等键、重复队列、worker接管和crash恢复测试 |

除总体值，还要报告视频长度、内容类型、静态/动态、ASR质量和事件持续时间分组结果。检索不返回结果不能提高回答precision而掩盖低召回，应同时报告可回答率、拒答率与答案覆盖。由模型给自己的高分不能充当独立ground truth。

## 4 时延与资源基线

先在明确记录的单机开发基线运行：建议16 vCPU、32 GiB内存、SSD；ASR与embedding是否使用GPU、GPU型号和模型规模单独注明。服务队列等待时间与实际执行时间分开记录。以下只作为v1性能关口初值，硬件变动需重新建立报告。

- 在1万片段、单workspace且索引已就绪的基准中，多路检索服务不含VLM复查的P95目标为2秒以内。
- 异步任务受理API不包含文件上传和后台执行，P95目标为1秒以内；初始压测为10个并发请求，报告排队和错误率。
- 问答与剪辑总时延拆成排队、检索、模型、局部解码、渲染，先报告P50/P95和token/图像使用量，不承诺统一秒数。
- 长视频处理禁止整片导出所有PNG或把完整音频频谱无限保留内存；流式媒体预处理worker的RSS目标不超过2 GiB，不含独立模型常驻权重。实测时记录该排除项。
- 成本以provider实际usage和有版本的价格表统计，缓存命中、输入图像、失败重试分开计数；不能使用每图固定346 token或整片固定价格。

## 5 必须执行的故障场景

上传中断并续传；worker在阶段提交前退出；重复投递同一任务；索引一半建成时失败；向量库暂时不可用；Flash超时、429和非法JSON；ASR无结果；声学与字幕冲突；对象写完而数据库尚未提交时崩溃；旧lease worker晚到；两个编辑请求使用同一expected_revision；幂等键复用不同payload；渲染完成与取消同时发生；用户修改后旧预览到达；SSE断线与重复事件；源媒体删除时仍有检索或渲染进行。

每种故障检查恢复结果和可见状态，不能只检查程序抛异常。重放后不得覆盖新revision、重复扣费记账或公开未验证artifact。请求已被provider接收但响应丢失时，费用可能存在未知项；记录估算和对账状态，不承诺绝对不会发生外部重复计费。

## 6 媒体成片验收

生成预览和导出后执行ffprobe、解码至null和关键帧核对。对固定帧率输出，时长误差原则上不超过2个输出帧；源音视频本身异常时需另列限制。跨片段同步检查音频起止、静音补齐、字幕平移、画幅fit/crop和旋转。视频可播放只证明容器与编码基本有效，语义还要检查选片是否符合EditBrief和证据。

自然语言编辑包含时长目标、必须包含与排除、排序、音轨保留、重复镜头去除等测试。约束冲突返回可解释原因，不能静默丢弃用户明确要求。结构验证和语义Review分别出报告，并保留同一revision_id。

## 7 安全与隔离验收

至少建立两个workspace，分别尝试引用对方的media_revision、evidence、artifact、image query、timeline、job和缓存。向量检索必须先过滤scope再取topK，不能先全库检索再删掉非法结果。删除与导出也遵循相同权限。

视频字幕和OCR可能包含“忽略指令”“运行命令”等内容；这属于素材证据，不能成为控制Agent的指令。测试模型被诱导生成越权工具参数、路径遍历、shell片段与外部URL，服务端都应拒绝。媒体worker只处理受控对象路径，FFmpeg不启用任意远程输入；限制资源与超时并及时更新依赖。

## 8 部署形态

开发环境优先复用现有Docker Compose，分别编排API、Web、媒体worker、模型/索引worker、MySQL、Redis、RabbitMQ、MinIO和Qdrant。生产根据实际规模分开worker并发与资源限制。图像embedding与ASR模型作为可替换adapter或独立服务，不要求所有开发机有GPU。

镜像和包版本应锁定，env.example只列键与说明，不存密钥。配置至少包含存储、数据库、队列、Flash base URL/model、专用模型ID、pipeline版本、采样预算、调用预算、媒体限制、保留期和允许的输出profile。健康检查分存活和就绪；依赖不可用时报告具体能力，不把所有服务显示为健康。

## 9 迁移与恢复

在测试副本执行expand migration、回填、校验计数与引用、切换读写路径、保留旧字段；确认回滚窗口后再contract。备份必须覆盖数据库、对象存储元数据/对象、索引generation manifest与配置版本。索引可重建，但重建期间旧generation仍需提供服务或明确降级。

恢复演练从空环境恢复一个包含源视频、证据、编辑revision与成片的项目；核对digest、引用、权限、预览和重新渲染。仅成功导出SQL文件不算完成恢复测试。

## 10 发布证据清单

release report应列出commit、依赖锁、迁移版本、模型能力探测与实际模型标识、环境配置摘要、每个AT状态、质量和资源基准、故障注入结果、真实演示视频、未完成项和回滚方法。所有强制AT必须有可追溯的运行结果；未跑记NOT_RUN，外部条件缺失记BLOCKED。

“应用完成”要求所有M0至M6强制能力和验收通过；若只完成M1，应明确称为显式剪辑闭环。如果性能或精度未达到门槛，可交付开发版本，但不能将其标记为最终发布版。
