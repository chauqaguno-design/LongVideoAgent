版本：1.0　日期：2026-11-23　状态：待实施、待验收

## 0. 文档用途与效力

本文定义目标产品及验收边界，供 Codex 与开发者按 Spec 驱动实施。本文不是上线报告；所有业务能力均需在目标仓库完成检查、开发和真实验收后，才能标记交付。需求 ID 使用统一 `REQ-*` 目录，不以模型回答、演示截图或 mock 测试替代真实能力验收。

范围以 [决策记录与事实依据](09_DECISIONS_AND_SOURCES.md) 为准；实体和状态以 [数据模型与接口实施说明](06_DATA_API.md) 及其引用的数据与 API 契约为准。每个功能进入实现前，先审阅对应 `specs/001-*` 至 `specs/006-*` 的 spec、plan、tasks；实现导致行为变化时先更新规范、记录决策，再修改代码。量化质量和性能门槛须在统一验收矩阵冻结，本文中的验收条件均为拟定产品要求，不能描述为已有实测结果。

## 1. 产品目标

VideoMind 面向拥有较长视频素材、需要查找内容并把相关片段变成成片的用户。核心闭环是：导入素材，了解处理进度，按文字或截图找到可信片段，沿原始时间轴复看，用自然语言或显式区间生成剪辑，修改预览，最终导出真实可播放文件。

产品首先解决三个具体问题：用户找不到发生某件事的位置；问答不能说明依据来自哪里；找到片段后仍需重新手工整理与剪辑。系统应保存可复查证据与版本化编辑决定，允许用户对结果作局部修正，而不必每次重跑整个长视频。

### 1.1 主要用户与场景

| 用户 | 典型任务 | 成功结果 |
|---|---|---|
| 内容创作者 | 从访谈、录屏、活动素材中整理主题片段 | 可预览、可修改、可导出的剪辑与来源清单 |
| 学习与研究用户 | 查找讲解、操作过程、画面细节与先后关系 | 回答附源视频区间，证据不足明确说明 |
| 素材整理者 | 跨同一项目的多条视频查找相似画面 | 有范围筛选、匹配依据和跳转入口的候选列表 |

首版以单一 Workspace 内的项目使用为主，保留多租户资源隔离。Agent Team 是后续执行能力，不要求用户理解代理消息、队列或模型调用协议才能完成任务。

### 1.2 既有能力与目标能力分开记录

参考仓库为 [Morimi-Kazuha/VideoMind](https://github.com/Morimi-Kazuha/VideoMind)。M0 必须基于实际 checkout 记录分支、提交、AGENTS、现有接口、数据库、任务队列和前端状态；只有在该提交上实际验证的能力，才能写进“已有能力”清单。既有 Python/FastAPI 分层、素材处理、检索、问答和前端是优先审计与复用的对象，本文不据此声称它们已经满足新需求。

| 类别 | 本规范的处理 |
|---|---|
| 现有代码可以复用 | 先验证行为和接口，补合同测试；不为统一外观而重写 |
| 现有字段命名含 visual | 检查真实来源；OCR 文本得分不能展示为图像向量匹配 |
| 长视频、截图检索、剪辑与恢复等目标能力 | 按本规范新增或改造，初始状态全部待办 |
| 外部模型、工具和性能 | 分别验收；没有真实凭据或硬件时标记 BLOCKED |

## 2. 范围与开发顺序

先完成一条不依赖智能检索的真实剪辑路径，再逐步接入视觉记忆与 Agent。每个里程碑都保留上一阶段的可用路径。

| 里程碑 | 用户可获得的新增价值 | 必须达到的出口条件 |
|---|---|---|
| M0 仓库审计与合同 | 清楚知道当前基础和阻塞项 | 审计清单、能力探测、schema、验收基线已建立；业务未实现不得标完成 |
| M1 显式区间剪辑 | 输入来源与起止时间即可得到真实预览和导出 | 时间线版本、修改、渲染、验证、下载完整跑通 |
| M2 长视频记忆 | 异步建立覆盖全片的基础观察与索引 | 分块处理、覆盖账本、ASR/OCR/视觉观察和索引原子发布可恢复 |
| M3 检索与证据问答 | 用文字或截图找片段并核查回答 | 多路检索、局部复看、引用跳转、全局查询覆盖检查通过 |
| M4 自然语言剪辑 | 把编辑意图转成有依据、满足约束的剪辑 | EditBrief、选段、时长约束、成片检查和多轮修订形成闭环 |
| M5 Agent Team | 对独立任务并行处理并保持一致结果 | 同 Flash 分工、持久任务、预算合并、单写时间线和故障恢复通过 |
| M6 发布验收 | 可部署、可运维、可回滚的产品 | 真模型合同、跨租户隔离、质量基准、故障注入、备份恢复与发布门槛通过 |

### 2.1 首版非目标

首版不承诺逐帧穷尽语义理解、任意动作精确识别、跨镜头人物身份确认、医学或司法级事实鉴定，也不承诺检索到了所有出现次数。视频编辑限定顺序拼接、原速、默认硬切与统一输出 profile；复杂转场、变速、多机位自动切换、自动作曲、配音克隆和任意特效编排不在首版范围。模型不能运行任意 Shell、SQL，不能通过生成参数扩大访问权限。

## 4. 业务对象与用户可理解的版本

Workspace 是资源与身份边界；Project 组织素材和编辑项目；MediaAsset 是逻辑素材，MediaRevision 绑定不可变原始文件摘要。替换原视频产生新版本，不能把旧引用悄悄指向新内容。ProcessingRun 表示一次处理尝试，IndexGeneration 表示一次可发布的检索索引。

Observation 保存模型或专用工具观察，Evidence 保存问题或编辑决定所用的来源及支持状态。CoverageRecord 记录哪些时间区间计划处理、已解码、模型已观察、针对当前问题验证过或失败。采样覆盖与针对问题验证覆盖必须分开。

EditProject 保存编辑目标；EditBrief 是用户意图和约束；TimelineRevision 是不可变编辑版本；EditOperation 是一次可追踪修改；RenderJob 只渲染一个固定版本。Artifact 包括原始素材、帧、字幕、预览、导出与验证报告。任务完成不意味着产物已经通过验证。

源视频区间统一为 `[start_us,end_us)`，以整数微秒保存；用户看到的分秒为派生显示。帧保留真实 PTS 及 time base，不能按 `时间×帧率` 伪造真实帧号。输出时间线位置与源时间分开，用户从成片片段始终能跳回对应源区间。

## 5. 功能需求与可验收行为

以下条目均为待实现或待改造需求。具体测试 fixture、命令与数值阈值在各 feature spec 和统一验收矩阵中固定，实施者不得为通过测试而下调验收标准。

### 5.1 项目与素材导入

| ID | 产品要求与验收条件 |
|---|---|
| REQ-PRJ-001 | 创建、重命名和进入项目；查看素材版本、处理状态和编辑项目。原始文件字节变化必须产生新 MediaRevision，历史引用保持原版本。 |
| REQ-ING-001 | 复用既有上传能力或提供续传；上传后校验大小、摘要、可解码流和时长。失败有原因，重复素材可复用合法已有版本；跨租户不泄露去重命中信息。 |
| REQ-ING-002 | 上传确认后返回作业 ID，分阶段异步执行；支持查询、取消、重试和断线恢复。单块失败能形成 PARTIAL，不把已完成块全部重算。 |
| REQ-ING-003 | 所有帧和片段引用保留源时间与真实 PTS；变帧率、非零起点和时间基变化的素材跳转验收通过后，才允许精细时间声明。 |
| REQ-ING-004 | 默认按 60 秒窗组织采样，每窗至少 4 个均匀点，额外事件预算默认每窗最多 4 个；预算不足明确降低处理范围或深度，不能只保留片头并显示全片已理解。 |
| REQ-ING-005 | 新索引构建期间旧 active generation 可继续检索；完成校验后原子切换。任何一次查询固定 generation，失败构建不污染已发布索引。 |

### 5.2 多模态记忆

| ID | 产品要求与验收条件 |
|---|---|
| REQ-MEM-001 | ASR、VAD 和音频异常信息均附源区间及版本。音乐、低音量、重复句等仅作异常线索，不能单凭标签丢弃转写或宣称无人声；转写缺失与检测未发现分开记录。 |
| REQ-MEM-002 | 区分人工字幕、ASR、OCR 和模型读图结果。关键文字可打开原分辨率帧/裁切核查；字幕与转写冲突保留两者，不设无条件“字幕胜出”。 |
| REQ-MEM-003 | Flash 输出结构化视觉观察，关联真实帧/片段、模型版本与采样信息；校验失败或图片合同不通过时标记失败，不生成伪观察填满覆盖。 |
| REQ-MEM-004 | 形成片段事件和章/段/片段/帧层次摘要；跨重叠窗口去重但保留证据来源。摘要提供导航，不能替代底层证据或充当事件总数。 |
| REQ-MEM-005 | 文本默认复用 BGE-M3；图像模型另做选型和基准。不同模型/维度/版本独立索引，截图向量不得和文本向量未经对齐直接比较。 |

默认片段索引从 10 秒窗、2 秒重叠起步，允许结合镜头及语句边界调整。参数作为版本化策略记录，并通过目标素材评测；上述默认值是实现起点，不是事件召回或动作识别的保证。

### 5.3 检索、复看与证据问答

| ID | 产品要求与验收条件 |
|---|---|
| REQ-RET-001 | 文字查询返回候选卡片：素材、源区间、缩略图、匹配摘要和证据状态；点击可跳到原片。空结果与任务尚未建索引必须有不同提示。 |
| REQ-RET-002 | 支持上传截图，在已选范围内做图像检索并定位候选时刻；截图文字可作辅助检索来源，但界面不得把只命中 OCR 标成图像匹配。 |
| REQ-RET-003 | 先执行服务端 Workspace/Project/Media 过滤，再各路召回、RRF 融合与可选重排；结果显示可理解的匹配来源，不把相似度伪装成事件发生概率。 |
| REQ-RET-004 | 候选可触发原片局部复看，加密序列采样、文字裁切或音频复核，细化边界；保存新 Evidence。最近邻帧与事件发生点不同，不自动视为同一时刻。 |
| REQ-RET-005 | “最初/最后/全部/次数”先定义范围，再核查该问题的验证覆盖。未穷尽时只报告已发现结果、已核查范围与缺口，不把有限 topK 当全部。 |
| REQ-RET-006 | 回答中的可核查主张关联 Evidence，显示 SUPPORTED/CONFLICTING/UNCERTAIN/NOT_CHECKED 对应文案。无法回答时说明缺什么证据及可执行的下一步，不补造事件或时间。 |

全局摘要使用层级记忆与时间覆盖，不强行依靠少量相似片段代表全片。动作顺序必须复看有序帧序列；单帧匹配、多帧平均向量或字幕中出现动词都不足以独立确认动作过程。

### 5.4 Agent Harness

| ID | 产品要求与验收条件 |
|---|---|
| REQ-AGT-001 | 通用 LLM/VLM 统一使用 DeepSeek Flash；默认配置 ID 为 `deepseek-flash`，部署时以官方能力探测冻结 resolved model。工具调用、图片输入各自做真实合同测试，不允许自动改用 Pro 或其他通用模型。 |
| REQ-AGT-002 | 只允许强类型注册工具，服务端执行资源范围、参数和权限检查。模型提交的 workspace、任意路径、命令或 SQL 不能成为授权来源。 |
| REQ-AGT-003 | WorkflowRun、计划与状态持久保存；对话只保留摘要及 artifact/evidence ID。上下文压缩、进程重启、浏览器重连后能继续同一任务，不把摘要当新证据。 |
| REQ-AGT-004 | 工具执行有持久幂等键与结果记录，事务外事件经 outbox 交付。重复消息和重试经对账后复用结果，不假定副作用天然 exactly-once。 |
| REQ-AGT-005 | 每次工作流有预算、超时、取消和有界修复次数。超过边界不新增工作；已运行作业给明确状态。预算调整有记录，不能由模型自行无限加价或循环。 |
| REQ-AGT-006 | 检索证据、素材字幕、OCR 和模型观察均是数据；其中的指令不得更改系统目标、工具权限或跨项目范围。用户记忆与视频事实分区保存。 |

工具与图片能力分别阻塞依赖它们的链路；显式区间剪辑等不依赖该模型能力的路径应继续可用。ASR、OCR、embedding、reranker、FFmpeg 是独立专用能力，不声称 Flash 能替代这些组件。

### 5.5 编辑、预览与导出

| ID | 产品要求与验收条件 |
|---|---|
| REQ-EDT-001 | 用户指定素材、起止和顺序，生成版本化时间线并真实渲染；区间越界、空区间、顺序不明确时返回具体错误，不以剪辑建议文本代替文件。 |
| REQ-EDT-002 | 自然语言形成 EditBrief，明确主题、来源范围、目标时长、允许偏差、选段偏好、音频和字幕策略。硬约束冲突或证据不足时展示可调整项，不静默删除约束。 |
| REQ-EDT-003 | TimelineRevision 不可变。patch 带 expected_revision 与 idempotency_key；相同 key/payload 返回相同结果，key 内容冲突或旧版本均报 409；服务端重算输出位置。 |
| REQ-EDT-004 | 渲染异步，固定 revision_id、profile、renderer_version；状态和日志可恢复。相同任务重复投递不产生重复可见导出，崩溃后先对账已有产物。 |
| REQ-EDT-005 | 先验证时间线结构与约束，再检查实际成片的解码、时长、音视频流和字幕映射。语义检查与机器校验分列；任一必要检查失败不能把导出标为成功。 |
| REQ-EDT-006 | 支持增删段、改源区间、换序、静音和回退；修改创建新版本。旧作业保留原版本结果但不覆盖新版本预览，过期工作流标为 SUPERSEDED。 |
| REQ-EDT-007 | 预览与导出绑定版本；源音频/字幕映射至输出时间线。无音轨素材明确补静音或按统一策略去音轨；烧入画面的字幕不可承诺独立移除。 |

首版 clip 必须含媒体版本、源起止、证据引用和 `audio_policy=keep/mute`；crop 和 caption track 可选。时间线含统一输出尺寸、帧率、音频采样率及 `caption_policy=none/preserve_source/burn_aligned`。`none` 表示不额外生成字幕，不代表去掉源画面已有文字。

预览显示“源区间”和“成片位置”两个概念。回退采用基于历史内容创建新 revision 的方式，保留修改记录。保存时间线与开始渲染不是一个不可分操作：用户可以先修改并查看计划，再请求预览；已授权的自动工作流可连续执行到可审阅产物，不增加逐步无意义确认。

| REQ-UX-003 | 播放跳转及预览版本可见；断线重连按 job/run/revision 恢复，重复点击不会重复创建工作。 |
| REQ-OPS-001 | API、对象存储、索引、任务、日志入口和下载授权贯穿租户隔离；越权请求不能通过模型提示绕过。 |

## 6. 状态、覆盖与费用的共同规则

ProcessingRun 使用 QUEUED/RUNNING/PARTIAL/SUCCEEDED/FAILED/CANCELLED；PARTIAL 表示有可用阶段或区块，也有缺口。WorkflowRun 的 WAITING_JOB 表示等待后台结果，AWAITING_INPUT 表示缺少用户必须决定的信息，不能用两者掩盖错误。RenderJob 进入 VALIDATING 后才可能 SUCCEEDED。IndexGeneration 的 READY 与 ACTIVE 分开，只有当前发布 generation 服务默认查询。

素材卡片至少显示总时长、可播放状态、ASR/OCR/视觉/向量能力、最近处理时间与缺口入口。覆盖记录里的 MODEL_OBSERVED 只说明模型看过指定采样；QUERY_VERIFIED 才说明针对特定问题检查过该区间，二者仍不表示模型必然识别正确。结果不得用“全片均已抽帧”推导“全部事件都已发现”。

费用面板分开显示模型调用、专用处理与存储/渲染资源计量；只有存在可追溯计价配置时换算金额。开始工作前展示范围、预计消耗依据和上限；实际执行随任务更新。预算不足时提供缩小范围、降低观察密度、延后深度复看或调整预算选项，并说明覆盖后果。用户取消后停止排队和新增调用，正在停止的 worker 与已产生费用如实展示。

### 6.1 需要统一的业务判断

**“最早发现”与“首次发生”不同。**例如两小时视频仅在前后若干窗口完成查询复核，系统可以返回当前证据中最早的候选，但必须显示此前未核查区间。只有对声明范围执行了约定检查，才能使用“在本次核查范围内首次发现”的限定表述；采样策略仍须可查看。

**计数以事件为单位。**同一次动作被多个重叠窗口或多张帧命中时先合并来源，再按明确规则计数；相似的重复动作不能因为画面相同而直接去重。无法区分两次发生时应给出不确定标记与候选区间，不能返回看似精确的整数。

**成片完成需要满足用户约束。**时间线合法、文件可播放，只证明结构与媒体处理成功；主题是否相关、是否保留完整语句、选择范围是否正确仍需证据或复看结果支持。如果硬约束未满足，保留可用预览并标注待修改，不把技术成功替代任务成功。

**用户的新修改优先于过期工作。**后台任务可保留已完成证据，但提交编辑时必须基于最新版本。任务中心应区分“已经取消”“仍在停止”“结果仅适用于旧版本”，既不悄悄丢弃产物，也不让旧结论覆盖新意图。

**资源删除与恢复具有不同范围。**取消一次处理保留原始素材；删除派生缓存不等于删除媒体；删除媒体会使相关引用失效。产品界面必须使用明确动作名，后端分别追踪回收状态。删除失败时说明哪些步骤待重试，不以界面移除一行代替完成实际清理。

## 7. 典型端到端验收剧本

**剧本 A：先验证真实剪辑。**用户上传两条可解码素材，手动选择三个源区间，保存时间线并渲染预览；删掉第二段后产生新 revision；旧渲染晚到时不能覆盖新预览；导出后验证时长、音轨与顺序，下载得到真实文件。期间模拟一次重复请求和一次 worker 重启，仍只有一个对应版本的可见导出。

**剧本 B：长视频理解到智能剪辑。**在含前、中、后段目标事件和干扰片段的固定样本上入库；用户按文字与截图分别检索，打开来源复看；要求“整理全部相关片段”时展示未验证范围；对已确认候选生成 EditBrief，满足目标时长与原声策略，修改后预览并导出。质量指标按冻结数据集评估，不能只展示一次命中案例。

**剧本 C：失败仍可解释。**关闭图片能力、模拟单块解码失败、索引发布失败、预算耗尽、字幕冲突与跨租户资源请求。系统分别表现为能力阻塞、PARTIAL、保留旧索引、等待调整、冲突证据和拒绝越权，不能转成看似成功的回答或导出。

## 8. 交付证据与发布判断

每项需求至少关联实现提交、合同/集成/端到端测试之一，以及可观察的产物或运行记录。涉及模型的测试保留 resolved model、请求能力、输入素材版本、预算与 usage；涉及渲染的测试保留 timeline revision、输出 profile、ffprobe/解码报告；涉及检索的测试保留 generation、候选与证据来源。mock 可验证编排，但不能替代模型图片能力、真实文件渲染和业务质量验收。

发布前应能够回答：用户是否得到其请求的可用产物；每个重要主张能否回到原片；失败和未知是否可见；重复与恢复是否安全；资源是否越权；成本是否有界。如果任何真实外部合同仍 BLOCKED，发布说明必须明确受影响能力，不能宣称所有功能完成。
