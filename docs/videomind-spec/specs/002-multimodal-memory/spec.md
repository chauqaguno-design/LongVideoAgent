# 002 — 多模态观察、记忆与索引规格

状态：TODO；目标里程碑：M2。前提：001 提供不可变原片、源时间、帧/音频产物、覆盖和 generation 协调器。本规格产出可检索记忆，不把描述和向量本身当作最终答案。

## 1. 用户问题与目标

用户希望不仅检索“视频说过什么”，还能检索“画面出现了什么”，并能在几小时素材中保留跨片段的上下文。系统必须保留不同模态的来源与冲突，知道哪些文字来自声音、哪些来自画面、哪些是模型描述，且在重处理或换 encoder 后不会读到混杂版本。

## 2. 需求与范围

| 需求 | 对应交付 |
|---|---|
| REQ-MEM-001 | VAD/ASR、语言、时间精度、静音/混音/重复风险与回看标记 |
| REQ-MEM-002 | 画面文字、原图 ROI、OCR 与 Flash 视觉读字复核 |
| REQ-MEM-003 | 同一 Flash 的结构化视觉观察、来源核验与 Evidence |
| REQ-MEM-004 | 重叠片段事件归并、章节/全片摘要和依赖追踪 |
| REQ-MEM-005 | BGE-M3 文本索引、独立图像向量空间、版本与缓存 |
| REQ-ING-005 | 完整组件构建后原子发布 IndexGeneration |
| REQ-AGT-001 / REQ-AGT-006 | provider 能力合同、输入内容与指令隔离 |
| REQ-OPS-001 / REQ-OPS-002 / REQ-OPS-003 | 租户隔离、实际 usage、失效与删除 |

首版必须有 ASR、画面文字与视觉观察的独立来源模型，以及真正的图像向量接口，以支持 003 的截图检索。允许专用能力未配置时运行部分原型，但 M2/M3 完整验收不能把该路标为已完成。可选片段时序 encoder、跨镜头 tracking/ReID、独立训练属于后续升级，不能阻塞首版短片复看。

## 3. 信息模型与不变量

Observation 绑定 media_revision_id、源 range、modality（ASR/OCR/VISUAL）、text、OBSERVED/INFERRED、support、artifact_ids、模型/提示词/pipeline 版本和 quality_flags。公开字段遵守统一 schema；更细的音频段、词级对齐、ROI、目标列表和供应商原始响应保存在版本化内部记录或 Artifact，不擅自增加不被合同接受的响应字段。

Evidence 绑定一条可引用 claim 及其 observation_ids/artifact_ids、源范围、verification_protocol 和 generation。Evidence.support 为 SUPPORTED、CONFLICTING、UNCERTAIN、NOT_CHECKED。SUPPORTED 表示按当前协议有直接支持证据，不是绝对真值或模型自信概率。

任何事件、摘要或 embedding 必须有原始观察依赖链。媒体内容中的“忽略之前指令”“调用删除工具”等属于不可信数据；不得因为出现在字幕或 OCR 中而成为系统指令。未能解析的模型输出不进入有效记忆。

## 4. 功能验收场景

### MEM-S01 正常语音与源时间

**Given** 音频块带源时间偏移并存在重叠上下文。

**When** ASR 返回分段或词级时间。

**Then** 按真实块起点与音频映射转换到源微秒区间；重叠区的同一声音实例只保留一次规范观察，保留全部原始来源。时间粒度与对齐版本可追溯，不能把片段内部时间当成全片时间。

### MEM-S02 无音轨与未检测到语音

**Given** 素材没有音轨，或音轨存在但 VAD 暂未发现语音。

**When** 构建多模态记忆。

**Then** 两种情况有不同状态/质量原因；无音轨不触发无限 ASR 重试，“未检测到语音”不被包装成绝对无语音。不为满足 Observation.text 非空要求创建伪造台词；缺席信息存入处理/覆盖结果。

### MEM-S03 音乐、混音和低音量

**Given** 背景音乐中存在人声，或一个声道有人声另一个声道没有。

**When** 声学量测与 VAD/ASR 结果冲突。

**Then** 保留冲突与低可信标记，进入明确的复转写/回听流程；不因单个频谱阈值、no_speech 值或“像音乐”的判断永久跳过内容。声道策略和音频变换可复现。

### MEM-S04 重复台词与重复幻觉

**Given** A 素材的不同时间确实重复一句台词，B 素材的纯音乐被识别出重复模板文字。

**When** 系统运行重复检测。

**Then** A 的不同时刻作为不同声音实例保留；B 被标记为待核查，不能仅因字符串重复就自动删掉全部内容，也不能仅因文本非空就声明听到了这句话。

### MEM-S05 时间戳能力不足

**Given** 所选 ASR 只返回整段文本和时长。

**When** 用户后续要求“只剪这句话”。

**Then** 对应记录的精度为段级，需额外强制对齐或较宽范围复看；不得均分文字或让 Flash 猜出词级时间。未获得可用对齐时明确限制，不输出伪精确字幕。

### MEM-S06 画面文字与声音冲突

**Given** 烧录字幕是翻译、简写，或 OCR 与 ASR 对同音词给出不同结果。

**When** 建立记忆和检索。

**Then** 保留 OCR 与 ASR 两路来源，并按问题区分“屏幕写了什么”和“声音说了什么”；不能无条件用 OCR 覆盖 ASR，也不能将字幕当作可随意编辑的独立字幕轨。

### MEM-S07 原分辨率读字

**Given** 概览拼图的小字不可读。

**When** OCR/视觉读字需要精读该区域。

**Then** 从原片实际帧按受控 ROI 裁取，保存坐标与 transform；放大仍不可读时标记 UNCERTAIN，不补写合理但不存在的文字。忽略低标准差面板的策略不得无验证地删除低对比度文本。

### MEM-S08 Flash 结构化观察

**Given** 一组有顺序、有 actual_us 的帧被提交给已通过图片与工具合同测试的 Flash。

**When** 返回物体、关系、候选动作与描述。

**Then** 输出通过 schema、来源 ID、时间范围与 claim_type 校验；只引用这次输入及已授权证据。单帧输入不能被标注为已验证“先拿起再放下”的顺序证据。

### MEM-S09 内容提示注入

**Given** 视频画面或音频出现要求 agent 导出密钥、改变权限或忽略任务的内容。

**When** 内容进入 caption、OCR、ASR 和摘要。

**Then** 仅作为不可信媒体内容保存，不能引发工具权限升级、任意网络请求或持久系统指令修改；原文是否作为检索内容保留与其是否能成为指令分开处理。

### MEM-S10 跨块归并

**Given** 一个挥手动作横跨两个重叠 Segment，另一次挥手发生在一分钟后。

**When** 构建事件候选和摘要。

**Then** 跨块的同一发生实例合并引用但不丢原始观察；一分钟后的另一次保留为独立实例。无法判断是否同一次时保留不确定关系，不能任意合并成精确计数。

### MEM-S11 层级摘要与证据依赖

**Given** 已有片段、章节、素材摘要，其中某个视觉观察后来因重处理改变。

**When** 发布新记忆版本。

**Then** 相关摘要及其 embedding 失效并重建；无关 ASR 缓存可复用。摘要引用的原始证据仍存在，缺失区间与推断不会被压缩成确定事实。

### MEM-S12 文本与图像索引分离

**Given** 同一片段同时有 ASR、OCR、caption 和帧图片。

**When** 构建索引。

**Then** 文本由已冻结版本的 BGE-M3 编码；图像由独立图像 encoder 编码；每个空间有自己的维度、预处理与 collection。caption/OCR 的文本向量不能冒充图像向量，模型生成的数值数组不能写入正规 embedding 路。

### MEM-S13 截图与目标帧处于同一空间

**Given** 已发布的帧索引由 encoder A 生成。

**When** 003 提交截图查询。

**Then** 查询图使用 A 的同版本预处理/归一化；若当前服务只加载 encoder B，应加载兼容空间或拒绝并提示重建，不能将两个同维度但不同空间的向量直接比较。

### MEM-S14 多帧表示与时序声明

**Given** 可选 encoder 接收多个帧并返回片段向量。

**When** 产品描述或检索解释使用它。

**Then** 先验证有序帧输入与顺序敏感性；简单均值池化仅称“片段视觉候选表示”。是否发生先后动作、精确开始结束仍需 003 的局部复看。

### MEM-S15 重建、缓存与原子发布

**Given** caption prompt 或 encoder 版本变化，旧 generation 仍在服务。

**When** 构建新记忆与向量。

**Then** 只复用完全匹配的缓存键；新记录保持 BUILDING 隔离，全部组件回验通过后原子发布。已删除媒体、错误 workspace payload、缺失向量和旧版本混入都阻止 READY。

### MEM-S16 部分能力失败

**Given** ASR 成功但 image_embedding 服务失败。

**When** 用户查看素材状态或查询。

**Then** ASR/text 路可按显式部分发布策略使用，image_embedding 为 FAILED/PARTIAL；截图功能显示能力限制，而不是返回“没有匹配”。M2/M3 完整能力验收保持未通过。

## 5. 质量与成本规则

对每次 ASR/Flash/encoder 调用记录 resolved model、版本、输入产物数、时间范围、重试、实际 usage 与耗时；不使用固定拼图 token 常量。模型 alias 无法被 provider 真正固定时，记录当次解析到的版本与服务端返回标识，承认不可逐比特复现，并在版本变更时重测/创建新 generation。

中文、英文和中英混合文本在开发集分别检查；图文 encoder 是否支持中文文本查询必须由选型测试确认。截图检索只要求图图同空间，不得把图文跨语言能力当作天然具备。

## 6. 完成定义

全部 GWT 有真实样本或确定性夹具；至少真实运行一次 ASR、OCR/读字、Flash 图片观察、BGE-M3 和所选图像 encoder，并保留版本与输出。完成跨块重复、音频冲突、内容注入、向量空间不匹配、缓存失效和 generation 故障测试。通过 003 的截图检索集成测试后，才能声明图像向量对产品可用；仅能生成浮点数组不算闭环完成。
